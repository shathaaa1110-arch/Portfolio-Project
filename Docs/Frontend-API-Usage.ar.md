# طريقة استخدام أداة الطلبات

كل طلبات الباك تمر من دالة وحدة في ملف الأداة.

```ts
import { request } from "@/shared/api/client";
```

## 1. الإعداد
انسخ ملف الإعدادات المثال إلى ملفك الخاص. للمطاعم والدخول الحقيقي استخدم `EXPO_PUBLIC_USE_MOCK=false`.
لتجربة ردود الحساب والتفضيلات والمطاعم المحلية، فعّل `EXPO_PUBLIC_USE_MOCK=true` وأعد تشغيل Expo.
هذا الوضع لا يرسل SMS ولا يحفظ التفضيلات في قاعدة البيانات.

```
copy .env.example → .env.local
EXPO_PUBLIC_USE_MOCK=true
```

## 2. طلب بدون تسجيل دخول
مثل قراءة المطاعم العامة.

```ts
const { restaurants } = await request<{ restaurants: Restaurant[] }>("GET", "/restaurants");
```

## 3. طلب يحتاج تسجيل دخول
مرّر رمز الدخول مع الطلب.

```ts
const prefs = await request("GET", "/users/me/preferences", { token });
```

## 4. إرسال بيانات
حط البيانات مع الطلب.

```ts
await request("POST", "/auth/request-code", { body: { phone } });
```

## 5. الأخطاء
أي خطأ يرجع بنوع موحّد. لو ما فيه نت أو تأخر الرد ١٥ ثانية، يكون نوعه خطأ شبكة.

```ts
if (error.code === "NETWORK_ERROR") { /* show "check your connection" */ }
```

## 6. البيانات التجريبية
كل ميزة تسجّل ردودها التجريبية في ملف خاص فيها.

```ts
registerMock("GET", "/restaurants", () => ({
  restaurants: [{ id: 101, name_ar: "Test Restaurant", cuisines: ["italian"], price_tier: 3, rating: 4.6 }],
}));
```


## 7. تفضيلات الحساب

استدعاءات التفضيلات في `frontend/src/features/preferences/api.ts`:

```ts
const saved = await getAccountPreferences(token);
await saveAccountPreferences(token, payload);
```

تستخدم GET وPUT على `/users/me/preferences`. يمرر غلاف الحساب الرمز،
ويحوّل `model.ts` إجابات النموذج قبل الإرسال وبعد الاسترجاع.
لا ترسل `user_id` أو `is_saved` في طلب PUT.
راجع [العقد والتدفق والاختبارات](Preferences-Implementation.ar.md).
في فحص OpenAPI المنشور بتاريخ ٢ نوفمبر ٢٠٢٦ لم يظهر مسار التفضيلات. ربط الفرونت لا يثبت نشر الباك.

## 8. صفحات المطاعم والبحث الشامل

داخل ميزة المطاعم، تستخدم الدالة `getRestaurants(offset = 0, search = "")` أداة الطلبات المشتركة:

```ts
const firstPage = await getRestaurants();       // limit=20&offset=0
const secondPage = await getRestaurants(20);    // limit=20&offset=20
// بعد تفعيل دعم البحث في البيئة:
const results = await getRestaurants(0, "شذ");  // limit=20&offset=0&search=...
```

يرجع الخادم `{ restaurants, total, limit, offset }`. لا يحتاج الطلب توكن. `limit` عدد عناصر الصفحة و`offset` عدد العناصر المتجاوزة. يتحقق الغلاف من الرد؛ الرد الناقص ينتج `INVALID_RESPONSE`، ويبقى خطأ الخادم `503 / RESTAURANTS_UNAVAILABLE` وخطأ الشبكة قابلين للعرض.

التدفق: `HomePage` ← `useRestaurants(searchQuery)` ← `getRestaurants(offset, search)` ← العميل ← الخادم. يحتفظ hook بصفحة واحدة، ويعيد البحث إلى الصفحة الأولى، وينتظر ٣٥٠ms عند الكتابة، ويتجاهل الرد المتأخر لطلب سابق. التالي والسابق في نهاية القائمة، والتحديث بالسحب يعيد الصفحة الحالية. فشل الصفحة التالية أو التحديث يبقي آخر نتائج ناجحة مع إعادة محاولة. لا تعرض نتائج البحث القديم تحت النص الجديد.

**حالة النشر:** الخادم المقروء في ٢ نوفمبر لا يعلن إلا `limit` و`offset`. إلى أن يُنشر #46، يبقى:

```dotenv
EXPO_PUBLIC_RESTAURANT_SEARCH_ENABLED=false
```

بهذا الإعداد تُخفى خانة البحث، وينقل زر «ألقى مطعم» إلى قائمة المطاعم دون فتح لوحة المفاتيح. تستمر طلبات التصفح العامة بـ`limit/offset` فقط. يبقى رفض `SEARCH_UNAVAILABLE` داخل طبقة API حماية لأي مستدعٍ آخر، لكنه ليس مسارًا تعرضه الرئيسية للمستخدم. بعد تحقق عاصم من الفلترة العربية/الإنجليزية **قبل التقسيم** وإجمالي النتائج المفلترة، يغير الفريق الإعداد إلى `true` ويعيد تشغيل Expo. المعامل `search` هو الاسم الموثق في `TechnicalDoc.md`؛ لا نستخدم فلترة الصفحة المحلية كبديل عن البحث الشامل.

## 9. تفاصيل المطعم

فتح نافذة التفاصيل لا يرسل طلبًا جديدًا؛ تستخدم بيانات البطاقة و`maps_url` لفتح الموقع. يظهر السعر فقط إذا وصل `spend_low` و`spend_high` كعددين صحيحين موجبين بترتيب صحيح؛ لا يُحسب مبلغ من `price_tier`. هذا دعم اختياري للعرض، وليس إعلانًا بأن الباك أضاف الحقول.

`reason` يمر من خدمة التوصيات بعد قراءة تفضيلات محفوظة إلى اقتراح اليوم ونافذة تفاصيله. لا يُضاف سبب مصطنع للمطاعم العامة أو المحفوظة. لا ساعات عمل أو تصويت في النافذة.

## 10. الموقع والترشيح الشخصي

يفتح شريط الموقع منتقيًا فيه GPS واختيار حي. لا يطلب GPS إذنًا حتى يضغطه المستخدم. اسم المدينة للعرض؛ الإحداثيات لا تُسجل في console ولا تُحفظ محليًا. إذا رُفض الإذن يبقى الحي والتصفح العام متاحين.

`personalSuggestions/districts.ts` يطلب `GET /districts` دون توكن. غلاف الرد النهائي يحتاج تأكيد عاصم؛ يقبل الفرونت مصفوفة مباشرة أو `{ districts: [...] }` بعناصر `{ id: string, name_ar: string, name_en?: string }`. تستخدم الطلبات المعرف النصي، ولا نحول اسم الحي إلى معرف مفترض. البحث داخل قائمة الأحياء محلي ويقبل العربي والإنجليزي.

بعد قراءة تفضيلات محفوظة، يطلب `personalSuggestions/api.ts` بالرمز:

```text
GET /users/me/recommendations?limit=10&lat=...&lon=...
GET /users/me/recommendations?limit=10&district_id=...
```

دون موقع يرسل `limit=10` فقط ويعالج `LOCATION_REQUIRED` بزر لتحديده. يعالج `DISTRICT_NOT_FOUND` بإعادة الاختيار، و503 بإعادة المحاولة. الموقع المختار كحي يعني مسافة تقريبية من مركز الحي.

الرد المتوقع `{ restaurants: [...] }` وفي كل عنصر ملخص المطعم و`match_score` و`reason` العربي و`distance_km` التي قد تكون null. يعرض أول عنصر في «اليوم؟ جرّب هذا!» والبقية تحت إجراء عرض بقية الاقتراحات. تحديث الرئيسية أو حفظ التفضيلات يعيد الطلب، وتغيير الحساب أو الموقع يمنع ظهور الرد القديم.

فحص OpenAPI في ٢ نوفمبر لم يجد التفضيلات أو التوصيات أو الأحياء. عند غياب الخدمة تعلن الواجهة ذلك؛ المطاعم العامة لا تتحول إلى نتائج شخصية تلقائيًا. لا تغييرات على SQL أو ERD.

## 11. بيانات حسابي

استدعاء بيانات الحساب في `frontend/src/features/auth/api.ts`:

```ts
const me = await getMyProfile(token);
```

يستخدم GET على `/users/me` ويرجع `id` و`name` و`phone` فقط.
لا يُرسل رقم المستخدم؛ يعرفه الخادم من الرمز.
الرمز المنتهي أو غير الصالح يرجع 401، فتمسح صفحة حسابي الجلسة وتعرض زر الدخول.

في وضع التجربة يحمل الرمز التجريبي الاسم والرقم، ويستلمه الرد التجريبي مع الطلب.
لذلك يبقى الحساب نفسه بعد إعادة التحميل، والرمز غير المعروف يرجع 401.

## 12. التحقق والتجربة الآمنة

تستخدم `features/sessions/api/join.ts` ثلاثة طلبات اتفقنا عليها مع عاصم، وهي موثقة في القسم 4.5 من [الوثيقة التقنية](TechnicalDoc.md):

- `GET /outings/by-code/{code}` بدون رمز دخول: معاينة الجلسة. السيرفر وحده يقرر إن كان الانضمام ممكنًا لشخص جديد، عبر `can_join` و`join_blocked_reason`.
- `POST /outings/{code}/join` برمز دخول الحساب.
- `POST /outings/{code}/join-guest` بالاسم فقط، ويرجع رمز ضيف يحفظه `guestPass.ts` لكل دعوة، فيرجع الضيف لمشاركته بدل أن ينضم مرتين.

يتحقق الغلاف من الردود، والرد الناقص ينتج `INVALID_RESPONSE`. وقبل نشر BE-09 يرجع المسار 404 بدون كود خطأ، فتعرض الشاشة أن الانضمام غير متاح حاليًا بدل أن تقول إن الرمز غلط. رموز التجربة في وضع Mock: `TEST` جلسة مفتوحة، و`MAXX` ممتلئة، و`SHUT` مقفلة، وأي رمز آخر غير صالح.

## 12. التحقق والتجربة الآمنة

`npm run check` يشمل ٥٩ اختبارًا بالإضافة إلى TypeScript والمعمارية. يشمل تحويل الحقول، حدود الأرقام، التصفح بالتقسيم، سباق البحث، إخفاء البحث غير المدعوم وانتقال زر الاكتشاف للقائمة، أخطاء الخادم، وتدفق الحفظ والتوصيات والانضمام برمز. [دليل التسليم](Frontend-Delivery-2026-11-02.ar.md) يميز التحقق الحي من التجارب المعزولة.

في اختبارات Mock استخدم نسخة محلية منفصلة، وضع القيم داخل `.env.local` وأعد تشغيل Expo. لا تعتمد على تمرير متغيرات الطرفية وحدها؛ اجعل عنوان API في نسخة الاختبار `http://127.0.0.1:1/api/v1` لمنع اتصالها بالخادم الحقيقي بالخطأ. يبقى إعداد النسخة الحقيقية `EXPO_PUBLIC_USE_MOCK=false`.


## 12. إنشاء الجلسة وتفضيلاتها والاقتراحات — ٦ نوفمبر ٢٠٢٦

`features/sessions/api/create.ts` يرسل `POST /outings/session` بحقوق حساب، مع الاسم و`starts_at` بتوقيت الرياض و`district` بمعرف حقيقي من `/districts`. `api/outing.ts` يقرأ الحالة والجاهزية، ويفتح التفضيلات، ويحفظها ويؤكد الجاهزية ويولد الخطة ويقرأها.

التفضيلات في `/outings/{id}/preferences` تخص نسخة الشخص لهذه الجلسة؛ لا تستخدم `/users/me/preferences` هنا. PUT يستبدل كل الحقول، لذلك نرسل الحساسية والميزانية والمسافة والجلوس والذوق معًا حتى لو غيّر المستخدم الذوق فقط. يلي الحفظ `POST /preferences/ready`؛ المنظم وحده يطلب `/start-voting` بعد جاهزية الجميع. هذا المسار يعرض اقتراحات حاليًا، وليس تصويتًا أو فائزًا.

رمز الضيف ورمز الحساب يمران في حقل `token` نفسه ويصبحان `Bearer`. لا نرسل التوكن في الرابط. `GET /outings/{id}` يتكرر كل ٥ ثوانٍ في الشاشة المفتوحة فقط؛ تعطل الطلب لا يُفعّل بيانات تجريبية تلقائيًا. [جدول المسارات الكامل ورحلة المبتدئ](Session-Flow.ar.md).

الروابط تدعم `/join?code=ABCD` و`/join/ABCD`. إذا أراد الباك توليد رابط ضيف، تكون `INVITE_BASE_URL` عنوان صفحة `/join` المنشورة. لا تغيير في مخطط البيانات أو عقد الباك؛ هذا ربط جديد للفرونت بالمسارات المنفذة في المصدر، ويحتاج تحققًا حيًا بعد نشرها.
