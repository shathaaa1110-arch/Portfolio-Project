# شاشات ذوق التعريفية مع هيلة

ثلاث شاشات متحركة مستقلة للتعريف بالتطبيق، بنفس شخصية هيلة والعناوين المرسومة المعتمدة. هذه الحزمة لا تشمل الصفحة التعريفية الطويلة.

| الشاشة | ما توضحه |
|---|---|
| ذوق يدلّك | البحث عن مطبخ وظهور خيارات المطاعم |
| نبدأ بذوقك | اختيار المطبخ وأثره في المثال، مع توضيح الميزانية والمسافة |
| من دعوة إلى جمعة | الدعوة وانضمام الأصحاب، ثم التفضيلات والجاهزية والتصويت |

صور المعاينة: [الاكتشاف](evidence/01-discovery.jpg) · [التفضيلات](evidence/02-preferences.jpg) · [الطلعة](evidence/03-outing.jpg).

العرض توضيحي ببيانات محلية. لا ينشئ حسابًا أو جلسة ولا يحفظ تفضيلات أو أصواتًا. زر «تخطّي» وزر «افتح ذوق» بعد الشاشة الثالثة ينقلان إلى [تطبيق ذوق](https://thouq.onrender.com). لا توجد شاشة رابعة.

## تشغيل المعاينة

من جذر المستودع:

```sh
python3 -m http.server 8883 --bind 127.0.0.1 --directory Docs/mockups/heila-onboarding/source
```

ثم افتحي `http://127.0.0.1:8883/`. أبقي نافذة الخادم تعمل أثناء المعاينة، واستخدمي `Ctrl+C` لإيقافها. لا توجد حزم للتثبيت أو خطوة بناء. GitHub يعرض المصدر، لكنه لا يشغّل HTML كصفحة تفاعلية.

## تنظيم الملفات

```text
heila-onboarding/
├── README.md                 ← التشغيل والشرح وحدود التسليم
├── VALIDATION.md             ← التحقق المنفّذ
├── evidence/                 ← صور الشاشات الثلاث
└── source/                   ← الحزمة التي يمكن نشرها كصفحة ثابتة
    ├── index.html            ← الإطار والأزرار وربط CSS وJavaScript
    ├── styles.css            ← الألوان والخط وتوزيع العناصر والحركة
    ├── app.js                ← المشاهد الثلاثة والتنقل والتحكم بالحركة
    └── assets/               ← الصور والخط وترخيصه
```

هذا التنظيم يتبع نمط `Docs/mockups` للمعاينات في المشروع. لا تُضاف هذه الملفات إلى `frontend/src/features` لأنها ليست ميزة Expo مدمجة بعد، ولا يتغير `architecture.json` أو عقد API أو قاعدة البيانات بهذا التسليم.

## كيف يعمل الكود؟

1. يقرأ المتصفح `index.html`، ثم يحمّل `styles.css` والخط والصور المحلية.
2. يشغّل `app.js` بعد قراءة HTML باستخدام `defer`.
3. المتغير `step` يحدد الشاشة: صفر للاكتشاف، واحد للتفضيلات، واثنان للطلعة.
4. `render()` يختار دالة المشهد من `[discovery, preferences, outing]`، ويحدّث رقم الخطوة والنقطة المختارة وزر التالي.
5. `requestAnimationFrame` يستدعي `tick()`؛ الزمن المنقضي يحدد مراحل ظهور العناصر عبر `phase()` وكلاسات CSS: `p1` و`p2` و`p3`. مدة المشهد ثماني ثوانٍ، ويتوقف بعدها. لا ينتقل للشاشة التالية تلقائيًا.
6. الضغط على مطبخ في الشاشة الثانية يستدعي `chooseCuisine()`، فيغيّر الصورة والسبب وحالة الاختيار داخل المثال فقط.

CSS يحدد **شكل** المشهد، وJavaScript يحدد **متى يتغير**. فصل الملفات اختيار لتنظيم الصيانة، وليس شرطًا يفرضه المتصفح.

في مشهد التفضيلات، ترتب شبكة CSS الخيارات ثم الميزانية والمسافة ثم الاقتراح ثم هيلة وردها. ارتفاع الصفوف تلقائي، ليأخذ النص مساحة إضافية عند التفافه على الجوال. لذلك تبقى الفقاعة أسفل بطاقة الاقتراح ولا تغطي سبب الاختيار. الحركات تغيّر ظهور العناصر دون تغيير هذا الترتيب.

## التحكم وإمكانية الوصول

- «التالي» والنقاط تنقل بين الشاشات الثلاث.
- «إعادة المشهد» يعيد الحركة للشاشة الحالية؛ «إيقاف الحركة» يوقفها، ويمكن استئنافها.
- عند تفعيل تقليل الحركة في الجهاز، تظهر العناصر في حالتها النهائية دون تشغيل الحركة تلقائيًا.
- للأزرار تسميات واضحة وتركيز ظاهر عند استخدام لوحة المفاتيح. يعلن عدّاد الخطوات تغيّر الشاشة، وتوضح `aria-pressed` المطبخ المختار.
- تبقى «تخطّي» رابطًا قابلًا للاستخدام حتى لو كان JavaScript معطّلًا.

## مصدر الرسومات وعلاقتها بالتطبيق

شخصية هيلة والخلفية المائية ورسوم المطابخ والعناوين المرسومة مأخوذة من التصور المعتمد مسبقًا. رسمة المطعم وورقة الدعوة مأخوذتان من `frontend/assets/images/sessions/`، لتبقى شاشة الطلعة متناسقة مع التطبيق. الخط نفسه المستخدم في `frontend/assets/fonts/`، وترخيصه محفوظ في `source/assets/OFL.txt`.

تستند رحلة الطلعة إلى `CreateSessionScreen.tsx` و`SessionScreen.tsx` و`components/SessionVisuals.tsx` داخل `frontend/src/features/sessions`. توضح اللقطة ترتيب الجاهزية قبل التصويت ولا تنفّذ هذه العمليات. مرجع أساس هذا التسليم هو `deployment` عند `92e5aa4` بتاريخ 24 نوفمبر 2026.

## النشر والدمج لاحقًا

لنشر المعاينة كصفحة مستقلة، يُرفع محتوى `source/` كما هو إلى استضافة ثابتة؛ يجب أن يكون `index.html` في جذر النشر وأن تبقى مسارات الأصول نسبية. لا يلزم خادم Python في الإنتاج ولا مفاتيح API.

هذا الـPR يحفظ الشاشات وملفات تشغيلها فقط. لا يغيّر نقطة الدخول أو تسجيل الدخول في التطبيق، ولا يضيف علامة «عُرضت أول مرة». ربط الشاشات بتجربة أول استخدام داخل Expo عمل منفصل.
