# تسليم واجهات شذى — سبرنت ٢ و٣

١٠ نوفمبر ٢٠٢٦. النطاق هنا مهام الفرونت الأساسية المسندة لشذى، مع تصحيح الرئيسية وحفظ الموقع المطلوبين. التغيير على `feature/session-creation-flow` في #159؛ لا يغيّر الباك أو الخوارزمية أو قاعدة البيانات، ولا يتضمن تحديث نسخة الآيفون.

## ما الذي أصبح موجودًا؟

| المهمة | التنفيذ في هذا الفرع | ما يلزم قبل إغلاق المهمة |
|---|---|---|
| #22 إنشاء الجلسة | تصميم الورقة والرسمة القديم، تحرير الاسم والموعد والحي، حفظ مسودة الدخول وزر إنشاء ثابت | اختبار الإنشاء والانضمام بالباك على جهازين |
| #66 تفضيلات الجلسة | نسخة خاصة لكل مشارك، الصحن و«وش مشتهي اليوم؟»، حفظ كل الحقول ثم تأكيد الجاهزية | تحقق حقيقي أن تعديل الجلسة لا يغير تفضيلات الحساب |
| #32 الاقتراحات وبطاقات المطاعم | انتظار هيلة أثناء الطلب، بطاقة واحدة مع السعر المتوفر والسبب والمسافة، «يعجبني / نتخطّاه» ومراجعة الإجابات | قبول التكامل الحي مع أصوات أكثر من مشارك |
| #34 النتيجة | فائز الخادم، التأييد من جميع المشاركين، عدد المكملين، توضيح التعادل عند حدوثه، مشاركة النتيجة، حالتا عدم التصويت وعدم الإعجاب | تجربة متعددة الأجهزة؛ حالة إعادة الجولة موضحة في #91 أدناه |
| #81 تفاصيل المطعم | نافذة مستقلة تحفظ موضع القائمة، السبب والسعر والمسافة المتوفرة، وفتح الخرائط أو توضيح غياب الموقع | API مستقل لتفاصيل المطعم وحقول الوصف وساعات العمل غير متاحة؛ تظهر القيم الناقصة بوضوح |
| #47 البحث والفلترة | بحث شامل بالاسم أو المطبخ، تأخير كتابة ٣٥٠ms، تقسيم النتائج، تجاهل الرد القديم وإعادة المحاولة | فلتر الحي والجمع بين فلاتر مستقلة ينتظران #46؛ لا فلترة محلية مضللة لأول ٢٠ نتيجة |
| #91 إعادة الجولة في الجلسة نفسها | تأكيد المنظم، نفس الدعوة والمشاركين، حفظ التفضيلات، جاهزية وأصوات جديدة، تجاهل الردود القديمة؛ مجرّبة محليًا | **الفرونت منفذ** بعقد مبدئي؛ تفعيل الباك ينتظر #90. الزر غير مفعّل على الخادم الحالي |
| #155 حفظ الموقع بعد تعديل التفضيلات | دمج إصلاح #162، تذكّر الموقع للحساب نفسه والعودة إلى الرئيسية الموجودة بعد الحفظ | اختبار GPS على الآيفون وثلاث دورات حفظ على الجهاز؛ لم تُحدّث نسخة الهاتف |

إعادة الجولة المحلية تحقق #91 من جهة الفرونت؛ إنشاء جلسة أخرى لا يحققها: المطلوب الدعوة والمشاركون أنفسهم مع جاهزية جديدة وأصوات جولة جديدة. لم نغير أي حد شخصي تلقائيًا كي تظهر نتائج.

عقد الربط المبدئي وحدود التفعيل في [Session-Retry-Contract.md](Session-Retry-Contract.md). لا تُغلق #91 قبل قبول التكامل الحقيقي.

## التغييرات التي طلبتها شذى في الشكل

- الإنشاء والدعوة والتفضيلات تستخدم الورقة والرسمة القديمتين؛ الخطوات أقصر والمشاركون في نافذة مستقلة.
- الأخضر ينتقل إلى «أخطّط طلعة» عند اختيارها، ويعود إلى «ألقى مطعم» عند اختيار التصفح.
- «اليوم؟ جرّب هذا!» يحتوي مطعمًا واحدًا. بقية التوصيات تظهر كبطاقات في القائمة تحت **«مطاعم أخرى على ذوقك»**، ثم قسم المطاعم العامة. لا زر توسيع يخفيها داخل اقتراح اليوم.
- شاشة هيلة تظهر أثناء طلب الاقتراحات الحقيقي. تأخير الثلاث ثواني موجود في المعاينة فقط؛ لا انتظار مصطنع في النسخة الحقيقية.

## أين نكمل أنا وفهد؟

كل المسارات التالية تبدأ من `frontend/src/`:

| المسؤول | الملفات | نوع العمل |
|---|---|---|
| شذى | `features/sessions/CreateSessionScreen.tsx`، `components/SessionEditors.tsx` | تصميم نموذج الإنشاء وحقوله |
| شذى | `features/sessions/SessionGenerating.tsx`، `SessionVoting.tsx`، `components/SessionRetry.tsx` | انتظار الاقتراحات، بطاقة التصويت، المراجعة والنتيجة |
| شذى مع تنسيق فهد | `features/sessions/SessionScreen.tsx`، `components/SessionVisuals.tsx`، `SessionLayout.tsx` | تركيب الدعوة والتفضيلات والجاهزية؛ مكونات مشتركة تستدعيها الواجهات |
| فهد | `features/voting/api.ts`، `useVoting.ts` | نقل الأصوات، الاستعادة وطابور الحفظ؛ تغييرات #161 محفوظة بكوميتاته |
| فهد مع تنسيق شذى | `features/voting/result.ts`، `features/sessions/api/outing.ts`، `api/round.ts` | أغلفة طلبات النتيجة والحالة والتفضيلات؛ تتبع عقد عاصم |
| شذى | `application/HomePage.tsx`، `HomeIntro.tsx`، `HomeTodayPick.tsx` | تركيب الرئيسية، الخيار الأخضر ومكان التوصيات |
| شذى | `features/restaurants/RestaurantList.tsx` و`components/` | قائمة المطاعم وبطاقاتها ونافذة التفاصيل |
| شذى مع تنسيق فهد | `application/HomeLocationBar.tsx`، `features/personalSuggestions/chosenLocation.ts`، `features/preferences/AccountPreferencesScreen.tsx` | الحفاظ على اختيار الموقع والتنقل بعد الحفظ؛ إصلاح #162 مضمن |

ملفات `app` مداخل صغيرة فقط. المكونات البصرية المشتركة لا ترسل الطلبات بنفسها. منطق الميزة يبقى في `features`، والتركيب بين الميزات في `application`، والاستيراد بين الميزات عبر `index.ts`. تعتمد `sessions` على `voting` بتصريح في `architecture.json`.

## التحقق وحدوده

- `npm run check`: TypeScript وحدود المعمارية و٩٩ اختبارًا. الاختبارات تشمل تعطل الشبكة، عزل الحساب، حفظ كامل التفضيلات، التصويت المتسلسل، الإقفال، النتيجة والتعادل.
- إعادة الجولة: اختُبر الإلغاء ثم التأكيد والعودة إلى الجاهزية والتصويت داخل الطلعة نفسها؛ صور التأكيد بعرض ٣٢٠ و٣٩٠ في `Docs/mockups/session-retry/`.
- معاينة ويب ببيانات تجريبية: الإنشاء → الدعوة → التفضيلات → الجاهزية → انتظار هيلة → بطاقات التصويت والنتيجة. فُحصت شاشات ٣٩٠ و٣٢٠ بكسل.
- فُحص اختيار حي ثم حفظ التفضيلات والعودة للرئيسية؛ بقي الحي وتحدثت التوصيات. فُتحت تفاصيل توصية إضافية وعادت للقائمة.
- طلبات GET عامة على الخادم الحي أثبتت البحث: 33784 مطعمًا دون بحث، 3730 مع `search=سعودي`، وصفر مع نص غير مطابق. قراءة OpenAPI تؤكد وجود مسارات التصويت؛ لم نرسل أصواتًا أو SMS حقيقية.
- لقطات الواجهات وتقرير المقارنة في `Docs/mockups/session-refresh/` و`design-qa.md`.

هذه أدلة تحقق محلية وقراءة عامة للباك، وليست قبولًا نهائيًا على الآيفون أو بين عدة أجهزة. لا تُغلق المهام ذات الاعتماديات الناقصة بناءً على المعاينة.
